# Context Handoff 中文说明

这个文件是 `context-handoff` 技能的中文补充说明。

保留 [../SKILL.md](../SKILL.md) 作为技能必须读取的入口文件；当工作语言是中文时，也应读取本文件以获取中文规则、中文措辞和中文示例。后续如果需要支持其他语言，继续使用同样的 locale 后缀命名方式，例如：

- `SKILL-cn.md`
- `SKILL-ja.md`
- `SKILL-fr.md`

## 技能目标

生成一份高密度、可继续执行的任务交接文档，在新线程、新窗口或后续会话中也能快速恢复上下文，而不需要重复阅读整段对话。

目标不是复述聊天记录，而是保留足够的连续性，让下一位代理或下一次会话能直接推进工作。

## 入口与语言规则

- 始终以 `SKILL.md` 作为技能入口文件。
- 如果当前工作语言是中文，在生成 handoff 之前也读取本文件。
- `SKILL-cn.md`、`SKILL-ja.md` 这类文件是语言补充，不替代入口文件。

## 调用示例

- `Use $context-handoff to generate a concise handoff for this task.`
- `Use $context-handoff to write a workspace handoff file and a new-thread summary.`
- `用 $context-handoff 为当前任务生成一份简洁交接文档。`
- `用 $context-handoff 把当前任务整理成可在新线程继续的 handoff，并写入工作区文件。`

## 工作流程

1. 在提问前，先从当前线程和工作区收集足够上下文。
2. 明确区分已确认事实与推断、假设。
3. 按固定结构压缩信息，重点服务于后续继续执行。
4. 在当前工作区写入 Markdown 格式的 handoff 文件。
5. 同时返回一段可直接粘贴到新线程中的简短总结和建议提示词。

## 默认行为

- 默认输出语言：中文。
- 代码标识符、API、命令、文件名保留原始语言。
- 默认文件名：`handoff.md`。
- 如果 `handoff.md` 已存在，且用户没有明确要求覆盖，则创建 `handoff-YYYYMMDD-HHMM.md`。
- 默认写入位置：当前工作区根目录。
- 如果用户指定目标路径或文件名，按用户要求写入。

## 必须使用的输出结构

Markdown handoff 必须严格按以下顺序组织：

```md
# Task

## Current Goal

## Confirmed Facts

## Key References

## Assumptions / Inferences

## Tried Already

## Open Questions

## Next Best Step

## Suggested New-Thread Prompt
```

## 内容规则

- 不要把猜测写成事实。
- 不要粘贴完整聊天记录，也不要贴大段逐字转录。
- 要保留已经执行过的命令、已经验证过的发现，以及已经证明走不通的方向。
- 优先使用可复用、利于继续执行的交接措辞，而不是对话式填充语。
- 至少提供一个可以直接发到新线程的提示词。
- 总结要高密度、具体，并面向继续执行。

## 各部分写法说明

### Current Goal

用一到三句话说明当前正在推进的目标。强调目标终点，而不是完整历史。

### Confirmed Facts

只写已经验证的结论。如果某一点尚未被证明，应移动到 `Assumptions / Inferences`。

### Key References

根据任务类型调整内容重点：

- 代码任务：包含精确文件链接、相关符号、执行过的命令，以及测试或构建状态。
- 调研任务：包含证据来源、已确认发现、假设，以及最值得继续的分析路径。
- 混合任务：两类信息都保留。

如果可以，优先提供带行号的可点击本地文件链接。

### Assumptions / Inferences

单独列出推断、倾向性判断或尚未证实的结论。中文中优先使用 `推断`、`尚未证实` 这类措辞，避免和事实混淆。

### Tried Already

这里要记录：

- 已进行过的搜索
- 已执行过的命令
- 已排除的分支或方案
- 已失败或不值得重复的尝试

### Open Questions

只保留那些会实质影响下一步动作的未解问题。

### Next Best Step

先给出最优先、最值得继续的单一路径。如果存在多个合理分支，要做优先级排序。

### Suggested New-Thread Prompt

写一段简洁提示词，用户可以直接复制到新线程。它应该：

- 点明任务是什么
- 指向 handoff 文件
- 告诉下一位代理从哪里继续

示例：

```md
继续处理当前任务。先阅读 [handoff.md](/abs/path/handoff.md) 和其中引用的相关代码，然后从“Next Best Step”开始继续，不要重复已经验证过的搜索和结论。
```

## 文件写入行为

创建 handoff 文件时：

- 只写 Markdown
- 除非用户另有要求，否则优先写入工作区根目录
- 对重要发现提供精确文件路径和行号引用
- 如果上下文过少，也仍然要生成一份轻量 handoff，并明确说明缺失了哪些信息，而不是编造内容

## 响应行为

写完文件后，回复中应当：

- 告诉用户创建了哪个文件
- 提供一段简短的聊天摘要
- 内联给出可直接粘贴的新线程提示词

如果当前环境不能写文件：

- 仍然在聊天中给出完整 handoff 内容
- 明确说明文件未能写入
- 仍然提供可直接粘贴的新线程提示词

## 中文措辞建议

优先使用这些表达：

- `已确认`
- `推断`
- `尚未证实`
- `已尝试`
- `下一步最佳动作`

避免使用模糊、弱约束表达，例如：

- `大概就是`
- `差不多`
- `可能应该没问题`
